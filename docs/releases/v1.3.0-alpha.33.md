# v1.3.0-alpha.33: typed open-fault capture output

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a33`; native project
version remains `1.3.0`. Implementation: `1908ecd9b293d4edd9b1e6339df956b98e35d3cd`.

This alpha publishes an output schema for `open_fault` in both MCP profiles.
It describes stable native header, thread, module, crash and integrity fields;
launcher context, optional RPC data and bundle verification are explicit. Root
and capture-row extensions remain open, and sparse legacy JSON does not need
to provide every native section. The schema does not change artifact decoding,
text JSON, evidence storage or the meaning of capture completeness.

The full catalog remains 27 tools / 84 parameters and grows to 17 structured
output schemas. The focused catalog remains 16 / 45 and now has 16 structured
output schemas: every focused tool publishes an output contract. A verified
bundle marker still means the bundle passed integrity checks; it does not
verify that the captured binary matches it or prove a root cause.
