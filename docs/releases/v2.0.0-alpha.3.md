# FaultDebug v2.0.0-alpha.3

Date: 2026-10-17 (Asia/Seoul)

## Scope and version class

This candidate adds optional `page_size` inputs (strict JSON integer, 1–200,
default 200) to `get_rpc_trace` and `get_incident_report`. It pages only
observed RPC event rows; totals and zero-based page numbering stay global, and
candidate, unresolved, artifact, process-relation, and application-field
context remains unpaged. Old requests omit the option and retain the 200-row
default. The focused profile stays at 15 tools and grows from 41 to 43 input
parameters; the full profile remains 27 tools and grows from 84 to 86.

Under the project's [versioning policy](../versioning-policy.md), this is a
backward-compatible **MINOR-class** addition after a stable release. Since
v2.0.0 is still an unreleased MAJOR target established by the alpha1 default
catalog break, this iteration is Python `2.0.0a3` / Git tag
`v2.0.0-alpha.3`. An alpha ordinal advances that target; it does not turn this
into a stable v2.1 release or satisfy the v2.0 acceptance gate.

This reduces the maximum number of observed event rows returned per call when
the client opts into a smaller page. It is not a full response-byte cap and
does not reduce artifact decoding or scanning. Glama TDQS impact is not
measured.

## Remaining release gates

Stable **v2.0.0 remains NO-GO** until the final candidate passes the full
provenance-enabled core/gRPC profile, Docker N=8/16/32 workload matrix, kind
Pod/container lifecycle checks, a fresh 1800-second soak, external libuv corpus
re-evaluation, and an independent stable audit. The Glama administrator pin,
deployment, rescan and score remain **NOT VERIFIED**. Cross-process native HTTP
topology, native clock ABI support, and external C/C++ install-to-first-evidence
validation also remain open.
