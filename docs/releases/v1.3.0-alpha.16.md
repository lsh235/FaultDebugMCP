# v1.3.0-alpha.16: discover source-bundle candidates

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a16`; native project
version remains `1.3.0`. This alpha adds a read-only `discover_bundles` MCP tool
to find root-relative directories containing `bundle.json` before a caller
uses the source inspection tools.

Implementation commit: `3ab501011374250181143a3e3c45e74558f09c49`.

Discovery returns only candidate paths, manifest file sizes and explicit
`verification=not_performed`. It does not read or hash manifest contents.
Malformed manifests may appear as candidates; `get_function_source`,
`get_call_relations` and `get_source_evidence` remain responsible for validating
the supplied bundle. Symlinked/non-regular manifests are marked rejected,
results are paged, and scans are bounded at 10,000 manifests.

The workflow is intended to reduce guessed bundle paths and rejected MCP calls,
and make the tool set more coherent. No numeric Glama TDQS improvement is
claimed: the score, external pin, deployment and re-scan remain unverified.
