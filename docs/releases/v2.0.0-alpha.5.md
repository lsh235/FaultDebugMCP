# FaultDebug v2.0.0-alpha.5

Date: 2026-10-17 (Asia/Seoul)

## Scope and version class

This candidate adds two user-selected MCP prompts: `triage_capture` guides a
bounded first look at one capture, and `investigate_incident` guides a
read-only review of one declared store incident. They are available in both
`focused` and `full` profiles and reference only tools present in both. Prompt
retrieval returns one user-role instruction message; it does not read evidence,
access a database, run tools, launch processes, or use the network. Existing
tool names, schemas, annotations, behavior, evidence, and native formats are
unchanged.

User arguments are bounded and JSON-quoted as untrusted data. The recipes keep
observed, derived, static-candidate, unresolved, and hypothesis fields distinct;
the shared incident recipe reads the `unresolved` section from
`get_incident_slice` because `get_unresolved` is not exposed in the focused
profile. Prompt argument bounds and descriptions are part of the generated
schema, so MCP clients receive useful field guidance in `prompts/list`.
Host clients decide whether to list or use prompts; model task completion is
not established by protocol tests.

Under the [versioning policy](../versioning-policy.md), this additive protocol
capability is **MINOR-class** relative to a stable v2 release. Since v2.0.0 is
still the unreleased MAJOR target, the package version is Python `2.0.0a5` and
the tag target is `v2.0.0-alpha.5`. This alpha does not close v2.0 stable gates.

The research and decision are recorded in the
[candidate research](../mcp-guided-prompts-research-v2.md) and
[feature review](../mcp-guided-prompts-review-v2.md).

provenance-enabled core/gRPC release profile, Docker N=8/16/32 workload matrix,
kind Pod/container lifecycle checks, a fresh 1800-second soak, external libuv
corpus re-evaluation, and an independent stable audit. Glama pinning,
deployment, TDQS re-scan, and external C/C++ install-to-first-evidence remain
