## Behavior

`faultdebug integrate --execute-target` requires `--execute-build`. Once the
isolated configure/build/index/bundle stages all pass and the bundle is
verified, the CLI runs the generated `run` stage. Each `--target-arg` is passed
in order as one argument; no shell command is constructed. The build-only
option still leaves target launch `NOT RUN`, and plan-only remains the default.

The target runs as the current user and may trigger external effects. This is
not a sandbox. The intended use is an explicitly selected bounded smoke
workload. Long-lived service lifecycle remains separate.

Target execution reports PASS only when there is exactly one checksum-validated
`.fault` artifact, the target exits zero, capture is complete and stable, at
least one function event is retained, and thread/RPC drop counts are zero. A
nonzero target may still leave a useful crash artifact but is not a PASS.

See the [research and decision](../integration-execute-target-research.md) and
[adoption guide](../existing-project-adoption.md).
