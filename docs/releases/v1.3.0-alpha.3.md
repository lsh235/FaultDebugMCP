# v1.3.0-alpha.3: bounded concurrent checkout and TCP fault recovery

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a3`, CMake/native project
`1.3.0`. Baseline `v1.3.0-alpha.2`, commit
`ecdc7473df7b470c59375ec02abbe8a86cd389b6`.
ABI v1, FDAR v1, semantic RPC schema v1 and evidence-store base schema v2 remain
compatible. Application locks and the separate retry database do not change them.

## Behavior

Checkout previously held its shared state/ID lock while waiting for every remote
call. The new bounded keyed lock lets distinct orders progress concurrently,
while duplicates serialize and reuse the completed result. State updates retain
short locks. Changed-quantity replays fail409, capacity fails503 and an expired
lock wait fails504 before downstream work. Locks are process-local; checkout
state and external side effects are not given a new durable transaction guarantee.

A local real TCP proxy exercises reset before forwarding, discarded complete
responses, delay and recovery. Native acceptance compares independently collected
multi-service sessions and keeps proxy observations separate from evidence used
to build native service relations. See the
[concurrency/fixture contract](../http-concurrency.md).

bundle verified 63 files. Local native acceptance used a real multi-process

used as native causal edges. Checkout and payment state remain memory-only;
durability is limited to the inventory SQLite replay transaction.
