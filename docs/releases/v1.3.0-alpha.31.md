# v1.3.0-alpha.31: typed incident-slice output

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a31`; native project
version remains `1.3.0`. Implementation: `89d07b30c89719961a887373214e28874eeae199`.

This alpha publishes a typed success/error `outputSchema` for
`get_incident_slice` in both MCP profiles. Known SQLite incident, artifact,
participant and source-reference columns are described while those rows accept
future store extensions. Producer-owned observed, derived, static-candidate,
unresolved and hypothesis payloads remain open JSON. Stored source references
remain claims until `get_source_evidence` verifies them against a bundle.

The schema records the existing page envelope and 200-artifact / 1,000-event
limits. It preserves conditional omission of `observed_event_total` in text JSON,
the payload-level `INCIDENT_QUERY_ERROR`, read-only access, evidence state, tool
inventory and response behavior. Full/focused profiles remain 27/84 and 15/44
tools/parameters; structured output schemas increase from 14/13 to 15/14.
