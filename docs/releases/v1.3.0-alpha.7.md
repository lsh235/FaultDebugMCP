# v1.3.0-alpha.7: existing-project adoption

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a7`; native project remains
`1.3.0`. Baseline: alpha6 commit `dfff591b808b9a85a608c5d2e95b7131ace40ab2`.

## Behavior

- `faultdebug preflight --binary PATH` reads an ELF executable and reports
  platform, Build ID, runtime linkage, hook imports, debug information and
  provenance. It does not execute or load the target. `ready` is static
  readiness; capture and dependency resolution remain `NOT RUN`.
- `faultdebug integrate` writes a command plan, a CMake bridge and shell script
  into a new, separate build directory. Preparation does not configure, build,
  or launch the existing project. The supported path is Linux x86_64, Clang 18,
  CMake >= 3.20, Ninja and an installed FaultDebug prefix.
- The explicit target is an owned executable; additional owned libraries are
  opt-in. Build finalization verifies the content-addressed source snapshot,
  compile database, linked Build IDs and generated source note before creating
  manifests and a bundle. Launch remains a separate explicit action.
- `fd_python_existing_project_adoption` is the offline mandatory acceptance
  gate. Optional cJSON/libuv checks need explicit source inputs and do not
  authenticate declared upstream revisions from a local tree hash alone.

The original source/build are not reused or edited by the helper. Existing
`CMAKE_PROJECT_INCLUDE` hooks, generated/external source, and some source-sharing
layouts require manual integration. Filtered instrumentation is directory
scoped and can affect another target that shares a translation unit; full
instrumentation or manual integration is required for that layout. This alpha
does not claim complete dependency coverage, arbitrary build-system support,
provider delivery, or stable acceptance.

Design sources: [CMake project include](https://cmake.org/cmake/help/latest/variable/CMAKE_PROJECT_INCLUDE.html),
[CMake deferred calls](https://cmake.org/cmake/help/latest/command/cmake_language.html#deferring-calls),
and the [Clang compilation database specification](https://clang.llvm.org/docs/JSONCompilationDatabase.html).
The [adoption guide](../existing-project-adoption.md) records exact workflows
and the prior pinned external-project evidence.
