# v1.3.0-alpha.5: generate Build-ID separate-debug packages

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a5`; native project remains
`1.3.0`. Baseline: alpha4 commit `5b73c89398b7c41107b637cb5293a5564589833d`.

## Behavior

The new `faultdebug debug-package` command accepts a fully linked `ET_EXEC` or
`ET_DYN` ELF with a GNU Build ID and DWARF sections. It writes a new package
directory with a stripped runtime, a GNU `.build-id/xx/rest.debug` sidecar, and
a manifest containing input/output hashes. The input is not modified; an
existing destination is rejected. Both generated ELFs must retain the input
Build ID, and partial output is removed on failure. The debug root is directly
consumable by alpha4's `--debug-directory` resolver.

No ABI, FDAR, RPC, evidence-store, or MCP tool schema changes are intended.
The command packages one ELF only; dependency collection, split-DWARF
companions, and source provenance remain outside scope.
