# v1.3.0-alpha.4: Build-ID-verified separate debug files

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a4`; native project remains
`1.3.0`. Baseline: `v1.3.0-alpha.3`, commit
`fa4c899a1cdf9b9782d6c529d7bd7cd9c2d6b7b0`.

## Behavior

Address resolution can now read a separate debug ELF from an explicit local
GNU `.build-id/xx/rest.debug` directory when the stripped runtime binary lacks
the requested symbol. The runtime binary Build ID must match the capture, and
the sidecar's own Build ID must match that same value. A mismatched sidecar is
ignored. CLI `inspect`/`fault-report` and MCP `resolve_addresses`/`get_fault_flow`
share the same resolver. MCP debug roots are restricted beneath the configured
artifact root. Symbol tables are cached per call so a batch of addresses reads
each ELF table once.

No ABI, FDAR, RPC, evidence-store, or required-tool schema changes are intended.
The MCP tools gain an optional root-relative `debug_directory` parameter.
