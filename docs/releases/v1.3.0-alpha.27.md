# v1.3.0-alpha.27: typed multi-capture incident report

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a27`; native project
version remains `1.3.0`. Implementation: `33b066364a342353e1f64df27e4c85fda10c6197`.

This alpha publishes a typed `get_incident_report` result in both MCP profiles.
The schema describes the stable report envelope, the normalized RPC event
fields with their request-local `artifact_index`, and the 200-event page
metadata. Producer-defined process-relation rows, static candidates, unresolved
diagnostics, and application field-value rows remain open JSON so the schema
does not narrow variable evidence. Existing text JSON, capture decoding,
report construction, and evidence classification are unchanged.

The change was researched and reviewed in separate commits and is bounded to
the MCP return contract plus its version/docs/tests. The full profile remains
27 tools and 84 parameters; focused remains 15 tools and 44 parameters. The
published output-schema count becomes 11 full and 10 focused.
