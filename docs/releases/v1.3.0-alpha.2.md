# v1.3.0-alpha.2: cross-process HTTP retries and transactional replay

Date: 2026-10-17 (Asia/Seoul). Python package `1.3.0a2`, CMake/native project
`1.3.0`. Baseline: `v1.3.0-alpha.1`, commit
`65c121e409585238119de5acf56c9411e9a410b7`.
Runtime ABI v1, FDAR v1, semantic RPC schema v1 and evidence-store base schema v2
remain compatible. The retry ledger uses a separate, opt-in application database.

## Behavior

An inventory receiver can commit a reservation and lose its response. Previously
the fixture held state in memory and had no restart-safe replay oracle. The new
`faultdebug.retry_ledger` commits a local SQLite callback mutation and its saved
JSON result in one transaction. The same operation/payload reuses that result;
a conflicting payload fails. Callback failure or an expired precommit budget
rolls the transaction back. External payment or network effects are outside this
transaction guarantee.

The [HTTP retry contract](../http-retry.md) defines the opt-in inventory fixture,
logical operation and attempt headers, replay/conflict behavior, compensation,
and limitations. Each HTTP attempt has a fresh numeric RPC and W3C span. Logical
operation and attempt labels remain application self-reports; service queries
copy them only onto existing native endpoint pairs. Labels never create an edge.

The acceptance runner starts independently collected caller and receiver
processes on dynamic loopback ports, restarts the receiver with a new generation
and the same database, and inspects native captures plus persisted business state.
A fixed fresh/replay workload reports wall time and avoided mutations. It does
not establish a universal speedup, multi-host behavior or large-scale capacity.

Reproduce the native/HTTP checks with:

```sh
cmake -S . -B build-alpha2 -G Ninja -DFAULTDEBUG_BUILD_TESTS=ON \
  -DFAULTDEBUG_BUILD_SHOP=ON -DFAULTDEBUG_ENABLE_PROVENANCE=OFF \
  -DFAULTDEBUG_PYTHON_EXECUTABLE="$PWD/.venv/bin/python"
cmake --build build-alpha2 --parallel 4
ctest --test-dir build-alpha2 --output-on-failure -E fd_python_doctor_benchmark
.venv/bin/python test/shop_http_retry.py \
  --boundary build-alpha2/test/shop/libshop_boundary.so --runtime-dir build-alpha2 \
  --output build-alpha2/http-retry.json
```

Choose a fresh output path for retained runs; existing evidence is never
overwritten. The upstream pydantic-settings lifespan forward-reference warning
remains visible; actual MCP checks passed with it. Local Clang18 doctor was
NOT RUN because that compiler is not installed; hosted Clang smoke is distinct.

## Open release gates

Stable acceptance remains **NO-GO**. Current-revision full provenance-enabled
core/gRPC release profiles, Docker N=8/16/32, kind/container lifecycle, a fresh
1800-second soak, external libuv corpus reevaluation and independent final stable
audit remain open. A GCC local build and hosted Clang smoke have distinct scopes.
Graph tools are unavailable in this session; source inspection does not establish
graph/index coverage.

The fixture has bounded explicit attempts rather than a general-purpose automatic
retry controller. It does not provide authenticated operation identity, native
clock/attempt ABI fields, distributed transactions, external-side-effect exactly
once delivery, database retention/compaction, or arbitrary order reopening after
compensation. Durable local replay and measured task completion are this alpha's
bounded F/G milestone; H/I/J remain separate work.
