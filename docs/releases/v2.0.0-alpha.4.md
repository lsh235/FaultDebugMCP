# FaultDebug v2.0.0-alpha.4

Date: 2026-10-17 (Asia/Seoul)

## Scope and version class

This candidate adds optional `page_size` (strict integer 1–200, default 200)
and `max_events_per_thread` (strict integer 1–500, default null) to
`get_thread_trace`. The first bounds outer thread rows; the second returns the
last retained raw events in original order. Existing calls keep all retained
events. When event shaping is requested, returned rows report
`faultdebug_view.events_omitted_from_view`; it describes only this response
view, never capture loss. Sparse or missing event arrays remain distinguishable,
and a producer field collision fails closed rather than overwriting evidence.

Under the [versioning policy](../versioning-policy.md), this is a
backward-compatible **MINOR-class** addition after a stable release. Since
v2.0.0 remains the unreleased MAJOR target established by the alpha1 default
catalog change, the package is Python `2.0.0a4` and the Git tag is
`v2.0.0-alpha.4`. The focused profile remains 15 tools and has 45 parameters;
the full profile remains 27 tools and has 88 parameters.

The large synthetic MCP fixture contained 1,000 retained events. An opted-in
80-event view reported 920 omitted-from-view rows and reduced serialized text
from 320,356 to 26,481 bytes and structured data from 193,529 to 16,302 bytes.
This measures the tested fixture and option only: it is not a response-byte
limit, does not reduce full artifact decoding, and does not establish a
Glama/TDQS score change.

## Remaining release gates

Stable **v2.0.0 remains NO-GO** until the full provenance-enabled core/gRPC
profile, Docker N=8/16/32 workload matrix, kind Pod/container lifecycle checks,
a fresh 1800-second soak, external libuv corpus re-evaluation, and an
independent stable audit pass. Glama pinning, deployment, TDQS rescan, and
numeric score are **NOT VERIFIED**. Cross-process native HTTP topology, native
clock ABI support, and external C/C++ install-to-first-evidence validation also
remain open.
