# FaultDebugMCP v2.0.0-alpha.2

Date: 2026-10-17 (Asia/Seoul)

## Scope

`get_evidence_summary` now accepts 1–32 unique root-relative capture names in
one call. It returns count-only rows in request order and aggregate observed
RPC, process-relation, static-candidate and unresolved reason-code counts.
Clients can compare a batch before requesting detailed histories. The focused
catalog remains 15 tools with 41 parameters.

The response adds `summary_schema: 2`; `schema: 1` continues to identify the
semantic RPC evidence contract. Each per-capture row reports local RPC status,
observed event count, static-candidate count and unresolved counts. Relation
diagnostics remain aggregate-only where they cannot be attributed to one
capture. No event histories or application-success verdict are added.

## Migration from alpha.1

The prerelease input changes from `{"name": "capture.fault"}` to
`{"names": ["capture.fault"]}`. The previous `artifacts: 1` and unresolved-row
shape becomes an item list and reason-count map. This changes an alpha contract;
there is no stable v2 consumer contract yet. Use `get_rpc_trace` or
`get_incident_report` when detailed diagnostics or observed rows are needed.
